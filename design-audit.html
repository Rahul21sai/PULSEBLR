PulseBLR · Design audit

Four rules, four breaks.

Twenty-seven Stitch-generated “3D” screens, measured against the design system PulseBLR already has. The screens are not badly drawn. They break the four rules the codebase documents as fixes — which is why implementing them faithfully made the app look worse.

Scope 27 screens tagged (3D), of 51 Method Playwright at 1440×900 / 390×844 Date 25 Aug 2026 Branch feat/spatial-redesign-and-tech-precision

Verdict

Competent template output with real bugs, designed for a product that doesn’t exist.

The repo’s own design system is the stronger artefact. It was hard-won: every rule in it records a measurement. The Stitch screens undo four of them, and the earlier implementation attempt carried that regression into the codebase.

The spine of the audit

The four rules, and what the screens did to them

These are numbered because they are a defined set of four named rules in app/globals.css — not a sequence invented for this page. Each one exists because something was measured and then fixed.

01

Tracking is a function of size

Broken

The repo’s ramp spans -0.042em at display sizes to +0.11em on uppercase labels, and display text uses Inter Tight rather than Inter. One letter-spacing across a whole ramp is the tell of a default type scale.

Inter Tight in 0 of 27 files. Headline, body and label all set to plain Inter.

02

Elevation is a ring plus a lift, never one blur

Broken

A single diffuse shadow reads as fog: no defined edge, barely separated from the page. The fix stacks a 0.5px hairline ring for the boundary with a soft offset shadow for the height.

40 large-blur shadows in 20 files — the exact construction the --lift tokens replaced.

03

Hairlines are alpha, not solid grey

Held

A solid #E5E5EA border looks like a light line on white and a darker line on the page grey — the same border reading as two weights. Alpha composites correctly on both.

33 alpha borders, 0 solid-grey borders. The one rule the exports respected.

04

One accent, rationed

Broken

Blue means “you can act on this” and is never decoration. Rationing one hue is what leaves the cover images — real content — as the only colourful thing on screen. Eight category gradients were deleted for this reason.

20 pure-black references in 8 files; category colour bars back on cards; blue used decoratively in 4+ places.

+1

Interactive surfaces press, they don’t lift

Broken

A hover-grow has no equivalent on a touch screen, and most of this app is used on a phone. Scaling down on :active reads as physical on both.

24 hover-grow transforms against 64 press-downs — and one live in the repo already.

Marketing where the product goes

The expensive one

The best-looking screen is designed for a product that doesn’t exist

Event Intelligence shows “12,450 Active Attendees”, “42 Concurrent Sessions”, “84% saturation”, “speaker velocity”. PulseBLR collects none of it. Building that screen means either fabricating numbers in the product or building substantial new data infrastructure.

Meanwhile the signals PulseBLR does have — and that Luma and Meetup cannot show — appear on zero screens: connectionScore, isTechEvent, company attribution, area clustering, source health, the contact graph. The connection meter, documented as the app’s signature element, is absent from all 27.

That is the whole gap between a competent redesign and a $10k one. The design should be built on the one claim nobody else can make: that you’ll leave having met someone worth meeting.

What shipped instead

Depth built from the rules, not against them

Spatial treatment on the feed and event detail, using the principles already in the file rather than breaking them to fake the impression of depth.

  • A third elevation rung. --lift-3 continues the existing ring-plus-lift series instead of inventing a new blur. Three rungs is a z-order, which is what makes layering legible.
  • Depth is static layering, not a hover effect. A perspective stage plus translateZ puts the event cover on its own plane — true at every viewport and on every input device, unlike a pointer tilt.
  • The depth material is the cover itself. A heavily blurred copy behind a crisp one. The light comes from real content, so it adds no new hue and costs no extra request. Suppressed when an event has no image, because blurring a flat category tint is a smear.
  • Motion is scroll-driven and CSS-only, wrapped in prefers-reduced-motion: no-preference so the setting is honoured by construction — verified to resolve to none under reduce, not merely to a 0.001ms duration.
  • A procedural WebGL field was built for the hero and then deleted. The feed already renders a real data-driven connection graph, so a decorative one beside it would have said less.

Found while verifying

Two regressions already in the codebase

Fixed

EventGridCard carried hover:-translate-y-0.5 and hover:shadow-[0_10px_34px_…] — both audit defects, live, from commit f373bef. Now raise pressable.

Eight resurrected gradients

Deleted

The .card-bar-* category gradients were back as unreferenced dead code, from the same commit that “implemented the Stitch design system across all pages”.

88px of horizontal page scroll

Pre-existing, fixed

The detail page’s description had overflow-wrap: normal, so a bare URL — one unbreakable word — pushed the document to scrollWidth 478 on a 390px viewport. On every event whose description mentions a link.

Out of scope
